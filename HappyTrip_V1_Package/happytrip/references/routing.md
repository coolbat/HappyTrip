# HappyTrip 路由与交互规则

## 1. 决策顺序

先核对有无实际素材，再识别明确模式和禁止修改项，然后判断照片类型。用户指定 A05 时不因为检测到人物就改成 A03；“只调光”不会自动触发美颜。模式需要但缺失的材料形成 needs_input，不以猜测替代。

从注册表读取 ID、模式名称、类别、输入范围和边界，再读取 mode_file。不要凭用户拼错的 ID 猜成完全不同玩法；可以提出一个最接近的名字让用户确认。

## 2. 明确意图与别名

| 常见表述 | 对应模式 |
|---|---|
| 去路人、清掉背景游客 | A01 |
| 曝光太过、调光、自然后期 | A02 |
| 稍微美颜、自然修肤 | A03 |
| 拍立得公仔、Q版出框 | A04 |
| 水彩明信片、景点明信片 | A05 |
| 把这栋建筑变贴纸，其他不动 | A06 |
| 把旅途碎片贴进行李箱 | A07 |
| 我的城市旅行海报、宠物公路海报 | A08 |
| 演唱会大片、音乐节氛围重构 | A09 |
| 饮品飞溅、美食炸弹 | A10 |
| 让 Chair 这个词组成椅子 | A11 |
| 加白色手写注释、箭头涂鸦 | A12 |
| 上面冰箱贴、下面保留原片 | B01 |
| 风景从明信片纸面立起 | B03 |
| 旅行玻璃球、雪景球 | B04 |
| 把风景融进人像轮廓 | B14 |
| 三格漫画、四格旅行故事 | B16 |
| 用照片串路线、行程地图 | B22 |

用户只说“贴纸”时，需要区分 A06 原位贴纸和 A07 行李箱拼贴。独立贴纸包不在 V1 范围，不伪装成已支持模式。用户说“公仔”时优先解释 A04 的具体载体；盒装手办不是本次 B01。

## 3. 自动推荐

| 素材与意图 | 建议 |
|---|---|
| 单张景点、想做纪念品 | A05、B01、B03 |
| 单张人物旅行照、想艺术创作 | A04、A08、B14 |
| 多张旅行照片、没有行程信息 | A07；有故事可再推荐 B16 |
| 多图且顺序已确认 | B22、A07；有经历再加入 B16 |
| 食物或饮品 | A10、A12 |
| 杂乱合照、强调不改人物 | 先确定保护对象，再 A01；可选 A12 |
| 曝光问题、没有创作需求 | A02，不搭售式串联美颜 |

每个建议只解释一句与素材的关系。没有素材只能按文字意图建议，不能声称“这张照片最适合”。不要把候选排名解释为社交热度或生图成功率。

## 4. 最少追问

照片里有多个主体时，先问要改谁；路线未知时先问顺序。次要题字可留空，风格使用当前模式默认值。用户已明确提供的地点与日期不重复确认。

常规单图已选模式且条件足够时直接执行，不再要求批准完整 PRD。需要更多调用、额外外部服务或与保护项冲突时，再针对该变化询问。

## 5. 示例交互

用户：“用 happytrip 把这张景点照片变成明信片。”

处理：核对照片可读 → A05 → 日期未给则省略 → 默认横版水彩 → 生图与排版 → 核对地标和文字。不要问年龄、行程预算、社交账户等无关信息。

用户：“这十张图做路线地图，顺序你看着办。”

处理：如果用户允许的是设计布局而没有真实行程顺序，不把上传顺序冒充行程；询问真实顺序，或提供明确不连线的地点集。若用户明确说“我只要虚构的视觉路线”，可以做艺术示意并记录其创作性质。
