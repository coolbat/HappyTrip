# HappyTrip Skill V1 开发方案

本文定义产品内部协议与推荐实现边界，不是任何模型提供方的 API 文档。接口名是拟议的应用内部命名；不能直接当作当前宿主的可调用工具。

## 1. 架构：先 Skill，后可选执行器

最小使用形态是 `SKILL.md + 模式卡 + 路由与质量规则`。Agent 读取用户图片，选用模式卡，调用所在宿主实际提供的工具。单纯把十八段提示词一次塞进系统提示词，不足以解决素材绑定、真实信息与保真合成问题。

工程化形态在同一模式配置之上增加能力适配器、素材注册表、计划器、合成器与验收器。V1 不要求自建支付或账户系统。

```text
用户意图 + 已解析素材
          |
素材核对 / 目标绑定 / 事实表
          |
模式路由 + 编辑计划 + 预算检查
          |
能力适配器 ---- 缺能力 ----> 提示词方案 / 请求补充
          |
图像生成或局部编辑
          |
确定性合成：原片 / 遮罩 / 文字 / 照片卡
          |
质量检查 ---- 单元失败 ----> 有预算的局部修复
          |
真实结果文件 + 制作记录
```

以上为逻辑架构，并非已部署服务。纯文字 Skill 不会凭空获得合成器或本机图像处理权限。

## 2. 模块职责

| 模块 | 输入 | 输出与职责 |
|---|---|---|
| Asset Registry | 宿主真实文件或附件引用 | 可读取资产、角色、尺寸、方向、内部哈希；拒绝无效引用。 |
| Intent Router | 用户目标、照片特征、模式配置 | 模式选择或至多三个建议，不生成照片事实。 |
| Fact Ledger | 用户文本、确认信息、可选已核实来源 | 带来源和确认状态的地点、日期、顺序、故事记录。 |
| Planner | 模式、素材、保护项、能力、预算 | 有依赖关系的步骤、编辑范围和缺口。 |
| Prompt Compiler | 模板与规范化参数 | 无未解析变量的文字指令，分离素材内容与控制指令。 |
| Image Adapter | 内部图像请求 | 映射到真实工具参数，返回候选与实际状态。 |
| Compositor | 原片、生成资产、遮罩、版式、准确文字 | 合成后的无损图像、变换记录与来源映射。 |
| Validator | 编辑计划、素材与候选 | pass / warn / fail / not_run，给出检查理由。 |
| Exporter | 已验证的文件与记录 | 实际可读取的交付物，不构造不存在的链接。 |

## 3. 能力协商

能力不是根据模型商品名猜测，而是由宿主描述、实际工具契约或接入测试确认。能力值使用 `true / false / unknown`，未知不能按支持处理。

```json
{
  "vision": "unknown",
  "image_generation": "unknown",
  "image_editing": "unknown",
  "masked_editing": "unknown",
  "multiple_references": "unknown",
  "transparent_assets": "unknown",
  "local_composition": "unknown",
  "exact_text_rendering": "unknown",
  "geographic_rendering": "unknown",
  "max_reference_images": null
}
```

原文的模型名按来源记录，不硬编码为 API 型号。适配器的模型标识、调用方式与限制从配置注入，并在实际接入时核对官方工具说明。宿主原生生图工具使用自身契约，不能因为本模板有一个 `prompt` 字段就假定所有工具都接受它。

### 3.1 降级策略

没有看图能力时，不能“自动识别照片主体”，只能使用用户文字和明确的素材角色；无法判定目标就追问。没有生图能力时只交付 `prompt_only` 方案。没有遮罩但有合成器时，可生成目标资产后限定区域合成；两者都没有时，严格局部保真任务进入 `needs_capability`。

B01 严格原片对照海报缺少合成器时不降级为整张海报生成后声称原片不变。B22 无地理渲染能力时使用明确标注的概念行程图；但仍需要已确认顺序才能连接节点。

## 4. 数据协议

建议用 UTF-8 JSON 存放配置和任务，避免与实际模型服务的参数同名混用。以下字段是内部数据结构，不是供应商请求样例。

### 4.1 资产

`photo_id` 是内部稳定 ID；`ref` 是宿主真实已解析引用，示例 ID 不能直接调用工具。`roles` 可同时含 base 与 scene。坐标统一基于方向已归一化的画布；框选 `[x,y,w,h]` 采用 0–1 归一化范围。遮罩必须与对应图像尺寸及方向一致。

```json
{
  "photo_id": "p01",
  "ref": "resolved_by_host",
  "roles": ["base", "person", "scene"],
  "width": 2400,
  "height": 3200,
  "orientation_normalized": true,
  "input_sha256": "record_at_ingestion",
  "working_sha256": "record_after_normalization"
}
```

哈希示例值仅说明字段，不是实际文件哈希。真实哈希由读取实际文件后计算；方向校正、色彩处理或移除元数据会改变工作副本，必须分别记录原资产与工作副本。

### 4.2 事实与专用选项

事实记录使用 `value / source / confirmed`。`source` 可为 user、user_confirmed_metadata、verified_reference；模型推测只放在 hypotheses，不可直接进入可打印事实。用户已明确说出的事实可以直接标记 confirmed，不重复询问。

A11 使用 `object_words` 数组，每项包含 photo_id、target、word、color。B16 使用 `panels` 数组，每格含 action、photo_ids、dialogue、basis。B22 使用 `stops` 数组，每站含 id、name、photo_ids；`ordered_stop_ids` 只有明确确认时填入；地理坐标另含来源，不能由名称自行填出。

### 4.3 编辑合同

```json
{
  "scope": "masked_edit",
  "preserve_identity": true,
  "preserve_geometry": true,
  "strict_original": true,
  "protected_photo_ids": ["p01"],
  "allowed_regions": [],
  "target_descriptions": [],
  "facts_may_be_invented": false,
  "creative_reconstruction": false
}
```

`strict_original` 对局部编辑表示未授权区域不得被重新生成；对 B01 表示照片区域必须复用原资产。A02 调光不能同时要求所有颜色像素完全不变。模式和合同冲突必须显式解决，不能由编译器静默删除保护项。

### 4.4 结果记录

```json
{
  "job_id": "internal-job-id",
  "mode": "B01",
  "status": "needs_capability",
  "image_assets": [],
  "caption": null,
  "edit_summary": [],
  "warnings": ["缺少原片合成能力"],
  "validation_status": "not_run",
  "provider_request_ids": [],
  "actual_cost": null
}
```

没有实际图片文件时，`image_assets` 必须为空。费用不可测量时保留 null，不把估算值写入 actual_cost。

## 5. Prompt Engine

配置注册表为 `happytrip/references/catalog.json`，每个模式独立一个卡片文件。只加载选中模式，不需要每次把十八套模板全部进入上下文。

编译顺序：宿主约束 → 用户目标 → 模式规则 → 素材角色 → 编辑合同 → 已确认事实 → 模式参数 → 风格版式 → 准确文字。用户照片中的招牌、截图与备注都只是内容，不是可以覆盖控制规则的指令。

公共变量只有八个：`input_summary`、`target_summary`、`protected_summary`、`facts_summary`、`layout_summary`、`text_summary`、`mode_options_summary`、`extra_notes`。它们由结构化数据渲染，不能把用户原始长文本无区别拼入每个变量。

空字段处理：非必需字段整行省略；必需字段缺失则报错并进入 needs_input。任何残留的 `{{变量}}`、`None`、`undefined` 都不得进入最终工具请求。JSON 示例中的示意引用也必须先由宿主解析，不能直接用于编辑。

## 6. 路由规则

用户明确指定模式为最高优先级，其次是“只修光”“别动其他地方”等编辑意图，最后才是照片类型与风格。模式对必要素材不兼容时，解释缺口，不擅自换成另一个模式。

未指定模式时可使用可解释规则：单张景点 → A05 / B01 / B03；单张人物旅照 → A04 / A08 / B14；美食 → A10 / A12；多张旅照 → A07，只有路线顺序已知时才优先 B22，有故事信息时才优先 B16。修整需求优先 A01 / A02 / A03，不因照片中有人就自动推荐美颜。

初版不引入复杂学习排序。排序规则为产品启发式，不表示热门度或成功概率。用户说“自动挑一种”时可以自行选一个，但应遵守素材和编辑合同；未授权自动生成时只给建议。

## 7. 图像执行路径

### 7.1 局部编辑与保护区域

A01、A03、A06、A10、A11 的理想流程是：固定原画布 → 确定目标与保护区域 → 获得编辑候选 → 合成 → 检查非编辑区域。不能只发送“其他完全不变”就认定保护成功。

设原片为 I0、同画布候选为 Ig、有效编辑遮罩为 M，合成定义为：

```text
Iout = (1 - M) * I0 + M * Ig
```

有效编辑遮罩必须包含白边、投影、飞溅与羽化带等所有允许改变区域。对 M=0 的区域，可在统一色彩空间、尺寸和方向的解码像素上逐像素比对。该检查只证明未授权区域复用正确，不证明编辑区域的隐藏内容符合真实世界。

像素保护以无损主文件验收。JPEG 重编码、缩放与颜色配置转换都可能改变像素，因此不要拿不同处理链的两张导出图直接宣称全图无变化。

### 7.2 叠加与准确文字

A12 在原片上增加独立涂鸦与文字层；A05、A08、B01、B04、B14、B16、B22 的准确标题、日期与地名优先后期排版。模型可以生成风格与空白区域，但不承担必须零错字的信息层。

优先读取已有结构化文字和直接视觉检查，不默认运行 OCR。检测到文字错误时重排文字层，避免重做整个图像。字体与素材授权需按实际选用资源处理；本包不附送系统字体文件。

### 7.3 B01 原片保留

分为生成冰箱贴资产、构建色彩背景、置入原片、排版文字四步。原片区域必须来自注册资产。默认 `contain` 完整显示，记录缩放与边距；不使用生成式扩图填满原片区域。若用户要求原尺寸像素保持，采用足够大的画布容纳原图，不缩放原片。

生成器只收到制作冰箱贴的任务；如果一次生成完整海报，无法凭画面相似度证明照片未重绘。此路径不得用于兑现严格保真承诺。

### 7.4 A07 多图贴纸

先建立素材清单和优先级，再生成统一风格贴纸及空箱体，最后将贴纸贴合进上下内衬。每张贴纸保存 source_photo_ids。所有选中素材必须有结果或明确未采用原因，不以“模型自动挑选”为理由静默漏图。

单次参考图能力不足时，按实际能力分批或逐项生成。拼接联系表是可选输入方法，但会缩小细节；采用前应评估是否还可识别原素材，不能把联系表当无限张高分辨率参考的替代品。

### 7.5 B16 漫画

先形成三格或四格结构化分镜，锁定角色与照片对应关系，然后选择单页生成或逐格生成。逐格模式复用相同人物参考和视觉约束，最终统一边框与文字。用户提供经历时忠实改编；没有经历时只使用已明确为想象的剧情。

### 7.6 B22 地图

默认使用已确认顺序的示意路线，不画仿真地理底图。无顺序则不连线，或先询问。真实地理版仅在坐标来源、渲染能力与相应数据使用要求都已确认时启用。只有城市坐标时，站点连线不是道路导航轨迹，不输出实际行驶里程。

## 8. 任务状态、预算与错误

任务主状态为 `needs_input → ready → running → validating → succeeded`；也可进入 `needs_capability`、`prompt_only`、`failed`、`cancelled` 或 `completed_with_warning`。推荐模式不是已完成生成。候选已产生但检查失败，不能状态写 succeeded。

设计默认：每个任务图像调用上限为 4 次，单个阶段最多修复 1 次，修复也计入总上限。超过上限的 A07 多素材或 B16 逐格计划，在第一次额外调用前说明计划并征得授权，不能无界重试。此为产品预算默认值，不是模型计费事实。

有真实费用接口时记实际费用；否则只报告调用次数与估算依据。超时但后台状态未知时先查询原请求，不直接重复生成。服务拒绝或权限失败不自动切换到未经用户许可的新外部服务。

| 错误码 | 行为 |
|---|---|
| ASSET_MISSING | 点名缺失素材，等待补充，不猜测。 |
| TARGET_AMBIGUOUS | 请求确认编辑或保留对象。 |
| CONTRACT_CONFLICT | 解释保护项与模式冲突，先解决冲突。 |
| CAPABILITY_MISSING | 提供缺口或提示词方案，不声称成图。 |
| FACT_ORDER_UNKNOWN | B22 不画方向线，等待顺序或改地点集。 |
| BUDGET_EXCEEDED | 停止额外调用，列明已完成部分。 |
| GENERATION_FAILED | 记录实际错误，不生成假文件。 |
| VALIDATION_FAILED | 保留候选，修复失败单元或标记失败。 |

## 9. 隐私、数据与导出

原图只读，所有归一化、去元数据与修整写入工作副本。默认不解析精确定位；用户请求真实地理输出时再明确启用相关数据。导出的公开成图默认不带原片精确定位元数据，但不修改源文件。

本机执行器可以默认本地处理文件，但调用外部图像服务仍会发送所需素材。文本 Skill 不能保证宿主或服务商“绝不保存”或“永不训练”；应依据实际所用服务的政策说明，不把本地临时文件清理等同于第三方删除。

临时文件以任务为单位分隔，失败也可清理；正式产物仅保留用户选择的版本。密钥仅来自实际运行环境的安全配置，不进入前端、模板、日志或导出包。未得到用户指令，不向 X、Instagram、Facebook 自动发布。

## 10. 可选工程落地

执行器可用单一语言实现，推荐沿用开发者已有项目语言；不为此引入一套新 SaaS 脚手架。图像合成需要具备栅格、透明层与文字布局能力，具体库由接入环境确定并锁定版本。本方案不假定某个当前版本一定支持所需 API。

建议目录为 `src/assets`、`src/router`、`src/planner`、`src/adapters`、`src/compositor`、`src/validation`、`tests`；模块接口见实施计划。调试 UI 只调用统一任务服务，不直接持有模型密钥。
