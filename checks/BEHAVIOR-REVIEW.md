# HappyTrip 独立前向流程复核

日期：2026-09-29。复核对象：`happytrip/SKILL.md`、原生工具执行说明和当时的本地计划器。由独立负责技能集成的代理执行，未改动实现代码或测试文件。

## 方法与边界

在临时目录实际创建 11 张 180×120 的合成 PNG 文件，将它们作为可读取素材，调用 `prepare_job(request, HostAdapter(capabilities), job_dir)` 并读取结果与计划。每项任务使用独立目录；临时素材与任务在结束后清理，没有改动用户照片或原文档包。

这些是程序可读的颜色/几何测试图，不是真实旅行照片。人物、站点与目标绑定来自测试请求，未声称从合成图识别了真实人物。宿主能力设置为可看图、可生成、可参考图编辑、可多图和透明资产；没有本地处理选择，所以本任务 `local_composition=false`、`exact_text_rendering=false`；无显式遮罩 API、无地理渲染能力。

没有调用任何生图工具、没有外部网络、没有计费调用。四项结果均为 `image_calls=0`、`validation_status=not_run`。本次验证了计划与停止条件，不证明实际修图、人物一致性、构图质量或艺术验收通过。

## 应有的用户交互

以下是根据实际计划评估的回复形态，没有发送给真实图片制作用户，也没有声称测试照片已完成制作。

1. A01：直接说明将移除指定路人并保留中间两位同行者，然后执行原生图像工具；不再询问已明确的保留对象。常规保护需要看图核对，不宣称背景像素已验证零变化。
2. B01：说明“最终海报必须复用原照片，原生生图无法证明未重绘”，让用户选择“用本地 Python 合成”或“先提供冰箱贴素材与排版方案”。此前已明确选择本地处理的用户不应被重复询问。
3. B22：请求真实站点顺序，或提供无连线地点集的选择；明确本地排版选择可以合并在同次必要澄清中。只有用户明确授权虚构视觉路线时才按创作记录处理。
4. A07：说明当前计划是 11 张贴纸加空箱体共 12 次，超过默认 4 次；提供保留所有素材并提高预算，或由用户明确缩减素材的选择。保留现有完整素材清单，不能自行只用前三张。

## 文档与接口检查

使用 `.venv/bin/python` 执行官方 Skill Creator `quick_validate.py`，实际输出 `Skill is valid!`。另检查 UI 描述长度与 `$happytrip` 默认提示词、两个请求模板 JSON 和新增文档的本地链接，全部通过。

四个前向场景未发现新的计划错误。集成对齐时发现中间版 compositor 输出 `sha256/checks` 而 finalizer 要求 `output_sha256/validation`；已反馈给实现代理统一。完整 compose→finalize 文件链路由实现回归测试另行验证，不能从本次四个准备阶段测试推定通过。

全部 18 种模式的真实照片与原生图像工具验收仍为 `not_run`。
