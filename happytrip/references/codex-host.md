# Codex 原生图像执行

本参考说明 HappyTrip 如何使用当前 Codex 的真实工具。实际会话的工具声明优先；缺工具时返回能力缺口，不自行猜造 HTTP 接口、模型 ID、密钥变量或远端适配器。

## 1. 工具与能力

使用 `image_gen.imagegen`；通过 `functions.exec` 时，对应 `tools.image_gen__imagegen`。已声明的字段只有：

| 字段 | 使用规则 |
|---|---|
| `prompt` | 编译后的模式指令、当前阶段目标、素材角色与保护项。 |
| `referenced_image_paths` | 所有目标图片均有本地路径时使用；路径必须存在、可读、已看过。 |
| `num_last_images_to_include` | 至少一个目标无本地路径时使用；取能包含全部目标的最小最近图片数，最多 5。 |
| `transparent_background` | 需要透明背景、抠图或透明装饰层时 `true`；其他情况 `false`；编辑已有透明图时默认保持透明。 |

两个参考图字段互斥。全新生成且没有任何参考图时都省略。不能把 `size`、`mask`、`model`、`seed`、`quality`、`output_dir` 或内部 `photo_id` 当作本工具字段。期望比例和构图写进 `prompt`，最终尺寸以实际结果为准。

当前契约提供看图、生成、参考图编辑与透明背景；没有暴露显式遮罩、逐像素保真、准确字体排版或地理地图 API。不要将“没有声明上限”理解为本地路径可无限输入；多图任务依据实际返回结果与可用参考容量规划，不能静默遗漏照片。

宿主有 `view_image` 时，本地参考图在编辑前逐张查看。只有内联附件且已在会话看过的图片可按会话引用编辑；如果两种机制都不能覆盖全部目标，要求重新附上缺失图片。不得把 PDF 插图、未给出的前次素材或相似网图冒充用户照片。

## 2. 常规生成与编辑

模式、目标与素材已确定时直接执行。可用本地执行器编译计划与提示词；也可按选中模式卡整理明确提示词，直接调用工具。执行器的 JSON 是内部记录，不是原生工具请求体。

一个使用本地参考图的实际调用形态：

```javascript
// @exec: {"yield_time_ms": 120000, "max_output_tokens": 1000}
const result = await tools.image_gen__imagegen({
  prompt: "此处传入当前阶段编译完成的提示词",
  referenced_image_paths: ["/实际存在且已看过的照片路径.png"],
  transparent_background: false
});
generatedImage(result);
```

执行前替换示意字符串。不要照抄示意路径调用工具。按工具约定等待生成；如果 `functions.exec` 返回运行中的 cell ID，才用 `functions.wait` 接续，遵守原生工具的等待要求。用 `generatedImage(result)` 交付，不向日志打印完整结果或 base64 数据。

只使用工具实际给出的本地文件或保存后的原始返回文件进入 `import`。保存返回字节不等于重新编码图像；不要用截图冒充原始输出。如果结果只能在会话显示、无法获得可读取文件，就交付内联图片并如实记录文件导入尚未完成，不伪造本地路径。

每次调用前记下计划阶段、引用素材、尝试次数和调用状态；每次结果后更新。服务超时且执行状态未知时保留 `unknown`，先恢复原请求状态。原生工具未提供实际费用或 provider ID 时留空，不能编造。

## 3. 本地合成选择

当前宿主要求：图像编辑默认使用原生图像工具；只有用户明确要求本地处理时，才可用 Python 做图片编辑或合成。Skill 内有 `compose` 命令不自动产生这项授权。

下列模式的最终交付依赖确定性合成：

| 模式 | 原生图像工具阶段 | 用户明确要求本地合成后 |
|---|---|---|
| B01 | 只制作冰箱贴资产或上方展示区域，不能生成下方“原片”。 | 用原始登记照片作为下半区照片层，默认 `contain` 完整显示，记录缩放。 |
| A12 | 需要装饰资产时生成透明涂鸦层；不生成新底图。 | 在原底图上叠加装饰、独立文字，避开受保护主体。 |
| B22 | 默认不需要生图调用，本地计划只排版现有原片与确认信息。 | 制作城市标题、拍立得与编号地点卡；可插入有来源的真实底图及路径。无顺序就不连线，字段见 [route-photo-map.md](route-photo-map.md)。 |

用户已经说“用 Python 合成”“在本地叠加原图”“用本地脚本排版”等，可直接执行对应本地阶段，不重复确认。只说“做 B01”“保留原片”尚未明确选择本地处理时，说明技术原因并提出一次具体选择，例如：

> B01 需要把原照片放进最终海报，生图工具无法保证原照片不被重绘。可以用本地 Python 将生成的冰箱贴与原片合成；或者先交付冰箱贴素材和排版方案。请选择制作方式。

这是当前工具的图像编辑约束，不是所有任务都要新增审批。涉及此选择的任务，在选择前可以完成素材检查、目标绑定、计划和提示词，但不要先消耗生图调用制作一个无法按合同完成的成图。

用户已明确要求本地原片地图排版时同样直接执行。开发、升级或测试这些本地功能属于代码实现任务，可制作所需开发预览，不把上面的普通修图选择流程误用为再次审批。开发预览中演示的数据要标记清楚，不冒充用户真实旅程。

同一规则也适用于计划中其他本地 compose 阶段，如 A05 的准确题字、A07 的箱内贴纸合成和 B16 的分格与对白。是否需要这些阶段以用户所选模式和实际 `plan.json` 为准；不能由脚本里存在 Pillow 就推定已取得执行条件。

用户不选择本地处理时，保留 `needs_capability` 或明确的素材/提示词交付。B01 不能改成全图生成后仍称“原片未重绘”；A12 不把生成编辑称为独立底图叠加；B22 不把相似照片重绘当作原照片卡。用户主动改为自由创作时说明合同变化，不冒充原模式严格保真成品。

## 4. 局部保护、文字和多图

A01、A03、A06、A10、A11 的常规生成编辑要提示保护对象并目视检查。若用户要求允许区域外像素完全不变，原生工具自身不能证明；需要用户明确本地处理、同画布候选、完整有效遮罩及合成后的像素检查。有效遮罩包括白边、阴影、飞溅和羽化；不能凭提示词宣称验证通过。

A02 调光会改变全图颜色，不能同时承诺颜色像素不变；构图和内容保护分别核对。B01 等比缩放复用原片可证明未生成式重绘，但不能称原尺寸像素或文件字节不变。

必须准确的标题、日期、地名与对白应逐字检查。需要确定性文字排版时走已获用户明确选择的本地合成；字形缺失、文字溢出或错误就只修文字层。A11 的文字本身构成物体，是生成内容，另验收拼写和轮廓。

A07、B16、B22 保留每个选中素材与产物的对应关系。原生会话引用最多 5 张的限制只约束 `num_last_images_to_include`，不能当作所有图像工具的统一限制。素材无法一次覆盖时，按阶段分批；分批、返工计入默认四次预算。仍无法满足时说明需要的素材选择或额外预算，不偷漏照片。

## 5. 结果检查

先检查实际输出文件、尺寸与透明背景，再看图验证该模式的实质要求。程序可证明素材被读取、文件存在、引用关系、遮罩外像素一致等；不能自动证明人脸一致、地标正确、背景自然或艺术质量。

把已运行的客观检查与目视检查分别记录。`import` 只登记真实候选，`finalize` 只依据实际检查记录收尾，mock 结果永远不是实图验收。没有实图时 `not_run`，有图未看过时待审。用户的艺术偏好认可另记，不能由技术测试代替。
